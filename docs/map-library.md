# 地图编辑与合并后清理

“建图与地图 → 我的地图”提供搜索、活动图置顶及编辑模式。编辑模式可重命名或删除；中文名称作为显示名保存，内部地图编号、原始数据和路线引用不改名。

删除把未使用地图原子移动到 NOS 地图目录中的 `.m20-trash`，从常用列表移除。回收站可恢复，不覆盖同编号地图、不自动启用；这一步暂不释放磁盘空间。

重命名只更新显示名称，可以在导航、采集或后台任务进行时使用。

需要真正移除文件时，在回收站选择该地图的“彻底删除”，确认地图名称和删除后果后点击“永久删除文件”，无需输入确认文字。这会移除该地图的点云、栅格及所包含的记录，无法从回收站恢复。已有路线定义保留，相关地图不可用时不能执行该路线；活动图及其他地图实际引用的文件不会被删除。

服务重启时，行走地图更新的“关闭”状态同时写回磁盘，避免旧的“采集中”标记永久阻止编辑；已保存的观测帧和版本不清空。真实占用错误直接显示具体原因，不再笼统报成权限不足。

选择完整续建/行走更新候选时，启用对话框提供“将已合并的旧版本移入回收站”，默认勾选，可取消。平台自动判断是否可以清理对应的一份直接旧版本：

- 操作者确认并主动启用新候选；不在途中自动换图。
- 新图已成为活动地图，电脑端导航栅格同步成功。
- 候选元数据标记包含完整旧图、直接基准匹配，原文件完整存在、无外部文件依赖，且未被对齐检查拒绝。
- 没有采集、保存、行走更新或占用该图的任务；其他地图没有通过文件链接引用旧图。

任一检查失败保留旧图并说明原因。新图启用成功而清理被阻止时，明确显示“新图已启用，旧图保留”，不会误报启用失败，也不会删除其他祖先版本或所有历史地图。

## 加载范围

电脑端：`platform_hub.py`、`map_catalog.py` 及页面脚本/样式。NOS：`bridge/map_service.py`、`bridge/root_actions.py`、`map_catalog.py`。部署包已加入新模块。依赖栈不变。

先完成离线验证，再在任务收尾后统一加载电脑端与 NOS 地图代理；页面刷新即可加载静态资源。不要只刷新前端就宣称后端已就绪。页面同时检查两端编辑能力版本，旧服务未更新时禁用编辑按钮并显示更新提示。

无需重启厂家定位/雷达/视频服务来加载编辑接口；只有用户真正点击“启用地图”时沿用既有定位重启流程。开发测试不得对真实地图执行删除、重命名、恢复或自动清理。

地图管理使用跨进程文件锁，与本平台代理的地图启用、导入及采集启动串行；回收操作再次核对活动图与机器人任务状态。任意外部程序绕过平台代理直接操作地图不在此锁的协调范围内。

## 验证

新增合成文件回归、桌面流程回归和前端状态回归；在独立演示中验证中文重命名、删除、恢复、活动图保护，以及确认启用后清理直接旧版本。严格区分演示流程与真实地图验收。
