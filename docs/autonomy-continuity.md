# 自主任务的连续执行与位置显示

自主探索的观察点与导航最终目的地有不同的停车规则。探索接近一个观察点时，仅在收到新扫描、能规划出相接通路时接续下一段；没有可核验的后续通路仍制动。单点导航和路线最后一个点保留到点制动及实际停稳确认。

探索选点会继续遍历剩余可达区域，已访问位置不会占满候选预算。暂时找不到远观察点时，可先向仍能获得新观测的近处通路前移；转向暂时受限时尝试现有退让方向。分批搜索未完成、局部受阻与覆盖完成分别处理。完成判定使用稳定的新扫描，不按重复空结果立即结束。按地图范围探索时，范围随新观测到的通道扩展；指定半径保留原设置。

持续下发行走指令但位置没有改善时，平台使用约 4 秒的实际位姿与命令窗口识别受阻。在新鲜感知和速度反馈齐全时，先请求停车，随后选择已核验的侧移、后退或小角度转向。一个受阻位置最多尝试三个不同方向，每个动作有独立时间及距离限制。仅改变目标、原地摆头或定位漂移不会重置整体无进展期限。

失败的平移方向记录在地图坐标系中。手动转过 90 度或 180 度后，新前方不会因为仍叫“前进”就被旧记录排除；转回原方向仍保留失败记录。转向不增加本轮尝试次数预算。

短暂的 SLAM 配对等待和网络读取超时可使用仍在原有效期内的缓存，不延长期限。点云稀疏、地面暂时被遮挡则经两层 HTTP 保留 `ground_observation_pending` 类型，立即停止使用旧场景并保持零输出，继续读取地面；新扫描恢复后自动接续同一任务。格式、坐标系、倾斜或连接归属异常不按遮挡处理；普通报错文字不决定缓存策略。

感知请求携带上一帧时间戳，已经出现的新帧立即返回，避免等下一帧时把当前帧等到过期。相同几何的扫掠计算复用结果，输入地面或障碍改变后重新计算。路径局部修复成功后立即接续，修复不成时改换目标或启动已有退让流程。

机身实体投影内的旧图残影自动进入临时起步通行层，无需操作者补拍地面或积累历史投票。缓慢离开时保留已经被机身实际覆盖的格，避免后半机身再次卡在同一残影；实时障碍与机身外的墙线仍由实际观测处理。融合新版本继承当前原图坐标时，启用过程自动接续定位，定位未就绪会保留旧版本。

手柄的姿态调节与实际行走状态需要单独核对，不能将站立状态 `MotionState=17` 或 `ControlUsageMode=0` 直接当作手柄已处于行走操作。厂商 `BasicStatus.Direction` 则是另一项：它决定正 X 轴的前进方向，`0` 为机头，`1` 为机尾。平台自主机身路径以机头为前方，不能只根据平台本地的方向按钮推断机器人实际方向。

## 人员跟随

跟随沿用显式点选与既有人员锁定。局部检查按短时动作、当前速度和停车范围验证机身扫过区域，不再把任意小转向都当作 90 度转弯检查。

暂时缺少地面观测时，任务可保持锁定并等待新扫描；若存在经过核验的小角度对准动作，可以先对准。未观测区域不会自动变成可通行地面，遮挡也不被直接认作选中的人。丢失人员或多人交叉仍停车，要求重新点选。原有动作幅度未在本次修改中提高。

`autonomy.follow_controller` 返回本次决定、实际受阻方向、缺测单元、候选检查及源帧序号。相同视觉帧可在其原有效期内接受新雷达检查，但新的 HTTP 请求或新雷达帧不会延长旧视觉帧的期限。

## 探索图的位置

`autonomy.map.observation` 包含 `live`、`age`、`stamp`、`frame`、`capture_id` 和说明。正常探索使用同步 SLAM 位置；暂停自主移动但保留建图采集时，独立只读观察器继续获取同一采集的位置，让手动移动和转向能反映在图中。观察器不规划、不发运动指令，也不改写规划器内部地图。

地图保存后显示最后观测，并隐藏旧运动路径。导航的全局位置属于另一坐标系，不直接覆盖本轮 SLAM 局部图的位置。新任务等待第一帧时清除上一轮图像；重复帧、断流及坐标系不匹配不能显示成新的当前位置。

## 暂停、继续与放弃本轮

异常暂停后可直接继续同一采集。继续操作保留原探索起点、已观测区域和历史，撤销旧控制命令，从两帧新的同采集位置重新规划；手动移动不会被误当成另一个 SLAM 原点。控制循环不会重复启动，迟到的继续请求不能覆盖已到达服务器的暂停。后端重启后内存探索历史不自动恢复，已有采集仍可走原接管入口。

“结束并放弃本轮”先停车再停止采集，跳过融合、不发布新地图版本，也不切换活动地图。厂商 `drmap stop_mapping` 自身会进行后处理，因此可能留下临时观测文件；只有归属唯一的本轮临时目录才被隐藏，归属不明时保留目录并明确报告。这个按钮不代表永久删除磁盘数据，也不会把失败的放弃请求改为保存。机器人端需加载对应 `discard_protocol=1` 接口后才开放按钮。

## 保存地图后的定位恢复

启用刚生成的融合候选时，仅在当前活动图、保存结果和候选项目清单确认来自同一次融合、保留完整旧图坐标系的情况下，继承本轮保存轨迹作为定位搜索依据。任意同名或相似名称地图不能获得这一资格。

恢复先核对保存时的完整姿态。若操作者在保存后移动或转向，则以该保存位置为中心重新搜索多种朝向，再用另一帧结构点云独立验证。通过点云匹配也不等于机器人已经恢复定位，仍需等待原厂正常状态读回。服务重启后若旧 SLAM 内存观测已消失，则使用现有最近可靠位置或厂商全图搜索流程。

## 近墙目标与导航准备

单点目标位于已知空地、但整机无法在精确位置或朝向站稳时，可在 0.65 米内搜索同一局部空地连通区域中的可达站立位置。界面同时保留原点击点与橙色实际终点，并显示调整距离。不会把未知地面当作空地，也不会把终点跨墙移到另一个房间。准确可达的原目标保持不变。

起点只有余量不足时沿用有界平移恢复。角落内的 L 形候选，仅在整段对角直线通过完整机身扫掠、实测地面及净空不下降检查后，才交给单段平移执行器。实际机身已经碰撞、缺地面或定位无效的情况不靠缩小模型解决。

显式点击单点或巡检启动后，平台可以先恢复定位，再重新规划/提交。只读规划预览不触发定位初始化或运动。启动请求携带 `client_intent` 与当前服务/连接代次；取消会撤销该意图，即使开始请求迟到也不能重新启动，更不会取消其他客户端的任务。前端关闭请求本身不等于服务器已撤销动作。

预览现在先后核对所选地图与机器人活动地图/栅格，避免两份坐标系都叫 `map` 就被混用。错图时引导同步实际活动图，不反向启用旧选图。起点与旧图重叠时返回盲区、结构匹配及观测票数摘要；仅同步期限或独立帧不足允许一次有界只读重验。确实需要识别当前位置时，操作者可选择“重新识别位置并重新规划”，即使原厂状态显示正常也执行结构恢复；成功只更新预览，不启动运动。

临时通行层与执行器统一使用有效的精确障碍 bounds 检查，避免一个障碍点把同一粗栅格内实际测到的地面全部抹掉。新逻辑不会给尚未观测的机身盲区补造地面，也不会把弱结构匹配的旧墙直接清除。

电脑切换 Wi-Fi 后，如果原 `--share` 私人网段不再匹配本机接口，后台仍会在 `127.0.0.1` 启动并说明共享暂未启用，不再让本地页面一起停止。原共享网段保留，不自动开放其他网络；非法或公开网段仍是配置错误。

## 验证边界

`test_exploration_flow`、`test_follow_control`、`test_follow_runtime`、`test_exploration_view` 和 `test_autonomy_map_view.cjs` 使用合成输入验证接续、有限恢复、原始帧期限、目标锁定及显示状态。

`tools/benchmark_exploration_flow.py` 的房间与受阻回放是理想运动学仿真，能比较同条件下的零输出和探索覆盖，不能证明真实机器的运动响应、地形通过性或整层无人值守能力。现场观测和机器人部署记录保留在各开发机忽略的运行目录。
