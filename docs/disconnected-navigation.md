# 导航与巡检的断联策略

任务开始前可选择：断联停车（默认）、断联后完成任务并停车、断联后立即沿原路返回、断联后完成任务再沿原路返回。默认电脑执行器和失联保护继续保留。后三项由 NOS 上独立的任务执行器接收完整路线，使用机内 AOS basic_server 与原厂导航；不依赖电脑持续发目标，浏览器不承担任务心跳。

## 操作与状态

断联策略随巡检路线选项保存；单点导航的策略纳入预览身份，修改后重新规划。驻机执行使用低速敏捷平地、正向普通导航，中间航点自动接续；暂不支持充电点、特殊动作点或到点人工暂停。机器人未报告对应驻机能力时，非默认选项不可执行，也不会悄悄退回其他策略。

电脑后台每秒独立核对状态；只有其机器人状态链路仍新鲜时才续心跳。连续5秒无心跳触发所选策略。短暂恢复心跳不会撤销已经开始的返程；重连只对账，不重新发送旧启动。操作者点击停止优先于继续/返程，收到对应取消回执并观察到新鲜停稳反馈后，才报告停止完成。

电脑链路故障与机器人本地故障分开：本地雷达/定位/控制反馈过期、急停、手动接管、地图或栅格变化、定位跳变、持续无进展等均请求停车。PC断联策略不覆盖这些条件。任务有最长时限，未确认停止时不下发下一点。

## 原路返回的含义

记录真实定位形成的有序轨迹，保留转弯和回环，返程按倒序邻接轨迹点逐点导航。原厂仅使用局部导航处理这些短段，不允许全局规划抄近路；每段检查地图、实时障碍和转向净空。新障碍、未知区或离开已走路线超过0.6米时停止。它不是回放历史速度，也不是从当前位置直接连线到起点。最后回到起点邻域并核对朝向，再确认停车。

轨迹采样和原厂导航本身有误差；代码与合成测试不等于真机已达到对应精度。返程绕障效果、窄道、通信抖动与控制模式保持，必须在停稳准备后按受控范围进行真机验收。

## 驻机部署与交接

本功能跨电脑核心和NOS驻机服务，不能只刷新页面。需要同步本批连接包、受管代理、传感器客户端、地图保护助手；电脑加载对应核心接入。默认不启用驻机运动。

加载前核对 NOS 到本台 AOS 的机内地址。在受管 NOS 服务的 systemd drop-in 中显式配置：

```ini
[Service]
Environment=M20_RESIDENT_NAVIGATION=1
Environment=M20_RESIDENT_AOS_IP=<已核对的本台AOS机内地址>
```

不是外部 Wi-Fi 地址，不以文档地址代替现场确认。正常部署安装器会准备地图保护锁 `.m20-catalog.lock`（root创建、读权限644），驻机启动与root切图/建图/重定位共用锁，任务未停车时拒绝这些冲突操作。改地图显示名等元数据不受该保护阻塞。

NOS启动从原记录恢复时仅进行取消/停车核对，不恢复旧运动。已预留目标编号在下发前落盘，用来防止复用旧回包并识别自身任务；检测其他控制端任务时不发送全局取消。任务、轨迹和电脑引用写入本机私有数据目录，不进入Git。电脑关闭或换网时，其观察连接关闭不发送额外速度/取消；机器人按已授权策略执行。服务崩溃或停止未确认时，界面如实显示待核对。

本批按协作边界以独立功能提交接入；共享工作区正在修改的控制/感知文件不直接覆盖。主聊天统一整合、加载、核对双方能力，再进行真机验收。

## 接口

电脑：`GET /api/nav/resident/capabilities`；现有 `/api/nav/start`、`/api/nav/goal` 增加 `disconnect_policy`，普通 `/api/nav/cancel` 仍负责主动结束。路线保存同样接受此选项。快照含 `resident_navigation` 和 engine=resident 的导航状态。

机器人：`/missions/capabilities`、`/missions/status`（GET）；`/missions/start`、`/missions/pulse`、`/missions/cancel`（POST），沿用代理令牌与来源限制。启动包含幂等任务ID、控制端ID、完整路线、地图名/栅格、PGM和YAML指纹及坐标系。取消可先于迟到启动到达并写入撤销记录。能力查询不创建机器人连接或运动。
