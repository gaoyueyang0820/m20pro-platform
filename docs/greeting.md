# 打招呼能力（Greeting）设计与查证记录

能力目标：让 M20 Pro 用**灯语**（可靠）与**原地俯仰点头/升降起伏**（实验性）向人打招呼。
本能力分两层交付：

| 文件 | 角色 |
|---|---|
| `greeting.py` | 纯逻辑核心：灯语帧组包、点头/起伏 20Hz 序列生成、前置安全检查。无任何 I/O，可单测，供平台集成复用 |
| `m20_greet.py` | 独立 CLI：现场一条命令打招呼，自带状态自检、心跳保活、异常清理。仅标准库 |
| `tests/test_greeting.py` | 单元测试（10 例，全部通过） |

## 使用方法

在 PC 上执行（与机器人同网段；每条命令默认机器人 IP `10.21.31.103`）：

```bash
python m20_greet.py --status              # 先看状态：MotionState / HES / Mode
python m20_greet.py                       # 灯语问好：绿色呼吸 4s → 恢复默认（最安全）
python m20_greet.py --style flow          # 蓝色移动流水灯
python m20_greet.py --style blink         # 白色闪烁
python m20_greet.py --nod                 # 灯语 + 俯仰点头（实验性）
python m20_greet.py --bob                 # 灯语 + 升降起伏（实验性）
python m20_greet.py --nod --stand         # 趴下时先自动起立再打招呼
```

## 安全边界（已实现）

1. **前置自检**（`greeting.precheck`）：点头/起伏要求 MotionState 处于 **17（RL 控制）** 或 1（站立），
   HES=0、未休眠、已停稳（速度阈值 LinearX/Y<0.08、OmegaZ<0.12）、常规/辅助模式；
   趴下(4)/软急停(2)/空闲(0)/开机阻尼(3) 一律拒绝，灯语仍可用，动作类自动降级为纯灯语。
   > **状态语义订正（2026-11-02 实机确认）**：17 不是"底层接管、需退出"，而是**完成站立后的
   > 正常可遥控状态**——平台 `platform_core._velocity_tick` 要求 17 才下发轴指令、
   > `point_navigation` 要求 17 才能导航。早期把它当作互斥状态是错的。
2. **同步前置检查**：实机模式下先校验再返回"进行中"，避免界面报成功、后台静默拒绝；
   灯语 4 秒后再核一次状态，期间状态变化则跳过动作只保留灯语。
2. **全程原地**：动作序列 X=Y=Yaw=Roll=0，不产生任何位移或转向。
3. **动作幅度**（2026-11-02 按要求放大并放慢周期：幅度大 + 周期短会让机身甩得太急）：

   | 动作 | 幅度（占最大速度比例） | 单周期 | 总时长 | 硬上限 |
   |---|---|---|---|---|
   | 点头（Pitch） | **0.50**（旧 0.25） | 1.6 s | 3.2 s / 2 次 | ≤ 0.7 |
   | 起伏（Z） | **0.45**（旧 0.20） | 1.8 s | 3.6 s / 2 次 | ≤ 0.6 |

   常量在 `greeting.py` 顶部（`NOD_AMPLITUDE` / `NOD_PERIOD_S` / `BOB_AMPLITUDE` / `BOB_PERIOD_S`），
   平台上点按钮的提示语会显示当前幅度百分比，便于现场对照。
4. **20Hz 连续下发 + 结束零轴 0.4s**，覆盖官方 500ms 超时保护。
5. **异常清理**：Ctrl+C / 任何异常立即发 `CustomMode=false` 恢复默认灯效 + 零轴归零。
6. **动作后恢复原运行状态**（2026-11-02 现场问题后新增）：打招呼前记录 `BasicStatus.Gait`
   与 `ControlUsageMode`，动作结束（或异常）后先发使用模式、再发步态（官方说明切换使用模式
   会把步态重置为基础步态，故步态必须最后发），随后轮询 `BasicStatus.Gait` 确认，
   未确认则写日志提示手动切回。核心函数：`greeting.locomotion_snapshot()` /
   `greeting.restore_commands()`。

   > 现场背景：一旦 `Gait` 停留在 `0x1003`（标准运动模式楼梯）等非敏捷步态，
   > 机器人按原方式行走会失效，用户会描述为"打招呼之后走不了了、处于姿态调节模式"。
   > 恢复逻辑把这种"模式被改动后不归位"的风险兜住。
6. **灯语本身零运动风险**：趴下、待机状态都可以执行，是默认档。

## 实机验证清单（上线前必做）

- [ ] `--status` 能收到 BasicStatus/MotionStatus 回报（确认回报通道）。
- [ ] 灯语四种预设逐一目视确认：呼吸/流水/闪烁/常亮，颜色是否与文档一致（绿=2 蓝=3）。
- [ ] `CustomMode=false` 是否确实恢复默认灯效。
- [ ] 站立静止状态下发 `--nod`：观察 Pitch 是否生效；不生效则确认"移动步态限定"是否扩展到了站立状态。
- [ ] `--bob` 同上验证 Z 轴。
- [ ] 点头过程中前后左右无位移（确认安全边界成立）。
- [ ] 中途 Ctrl+C：灯效恢复、机器人保持站立稳定。
- [ ] 趴下状态执行：确认自动降级为纯灯语、无任何动作指令发出。

## 平台集成（已实现）

| 入口 | 说明 |
|---|---|
| 网页：运动控制页 → 「照明与方向」→ 打招呼·迎宾 | **灯语问好** / **点头问好** / **起伏问好** 三个按钮 |
| HTTP：`POST /api/cmd` | `{"action":"greet"}`、`greet_flow`、`greet_blink`、`greet_solid`、`greet_nod`、`greet_bob` |
| 命令行：`python m20_greet.py` | 现场快速验证用，支持 `--status/--nod/--bob/--stand` |

实现要点（`m20_platform.py`）：

- `Platform.greet(style, motion)` 在后台线程执行，动作类期间**持有 `link.drive_lock`**，
  让 20Hz 保活环暂停，避免保活零轴帧覆盖点头/起伏的 Pitch/Z 序列；异常自动恢复灯效并归零。
- 实机：走 `link.command(1101,14,…)` 灯语 + `link.command(2,21,…)` 轴序列，前置自检同 CLI。
- **演示模式（self.demo）**：不产生任何 UDP 指令；灯语只记日志，动作类用 `_greet_demo`
  在 `snapshot()` 里叠加合成姿态（点头 Pitch ±0.12 rad、起伏 Height ±0.04 m），
  界面可预览效果并标注"合成数据，非实机动作"。
- 实机模式但未连接 AOS 时，动作类问候明确报错，不静默失败。

> 排障记录：演示叠加最初用 `time.monotonic()` 记录窗口，而 `snapshot()` 的 `now` 是
> `time.time()`，两个时钟直接比较导致窗口被判过期（点头无可见效果）。已统一为同一时钟。
> 同类混用在 `autonomy_runtime.py` 里也存在，见问题检测报告 J4。

## 已知限制

- Cycle 是整数秒，闪烁/呼吸最短 1s 周期，无法做快闪效果。
- 灯语颜色只有黑白绿蓝四种（协议限制）。
- **起伏（Z 轴）在敏捷平地步态（0x3002）下实测无高度变化**（2026-11-02，MotionStatus.Height
  在 3.6 秒序列内恒定 0.505 m），与官方"移动步态仅有 X/Y/Yaw 生效"的说明一致。
  若要让起伏生效，需要临时切到标准运动模式（0x1001/0x1003）再切回，属于额外模式折腾，
  当前未实现；需要时再评估。
- 点头（Pitch）实测不改变 `Gait`，可作为安全保留动作。
- 点头/起伏未经实机验证（文档明确移动步态不生效，站立状态无背书），
  首次上机请有人在急停按钮旁。
