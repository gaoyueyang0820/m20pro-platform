# 设备异常状态上报


basic_server 以 2Hz 固定频率向心跳来源 IP/端口主动上报；当异常发生或解除时，会额外立即上报一次。


| Type字段值 | Command字段值 | 消息类型 |
| --- | --- | --- |
| 1002 | 3 | 获取异常状态信息 |


文档中出现的所有 Type / Command 均为十进制数字。

JSON格式响应：


```json
{
	"PatrolDevice": {
		"Type": 1002,
		"Command": 3,
		"Time": "2023-01-01 00:00:00",
		"Items": {   
			"ErrorList":[
			{
				"errorCode": errorCode,
				"component": value
			},
			{
				"errorCode": errorCode,
				"component": value
			},
			…//其它省略的错误
			]
		}
	}
}
```


XML格式响应：


```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
  <Type>1002</Type>
  <Command>3</Command>
  <Time>2023-01-01 00:00:00</Time>
  <Items>
    <ErrorList>
      <errorCode>errorCode</errorCode>
      <component>value</component>
    </ErrorList>
    <ErrorList>
      <errorCode>errorCode</errorCode>
      <component>value</component>
    </ErrorList>
  </Items>
</PatrolDevice>
```


一次响应可能包含多组ErrorList，每组ErrorList包含以下参数项：


| 参数项 | 含义 | 数据类型 | 单位 | 参数值说明 |
| --- | --- | --- | --- | --- |
| errorCode | 错误码 | int | / | 详见错误码表 |
| component | 发生错误的部件位置信息[7] | int | / | 以bit位作为部件号 |


[7] 当关节或电池发生异常时用于确定发生异常的具体关节或电池。关节编号可参考"1.3.1.2 运控状态上报"部分中的 <MotorStatus>参数组，按照FL/FR/BL/BR+HipX/HipY/Knee/Wheel的顺序从低位到高位进行编号，例如0x21（0000 0000 0010 0001）则表示：第一个关节（第0位，LeftFrontHipX关节）和第6个关节（第5位，RightFrontHipY）出现errorCode所表示的错误，其它关节的位号依此类推；电池编号的第0位表示后侧电池（靠近硬急停按钮的一侧），第1位表示前侧电池。

errorCode的值对应的含义如下表所示：

# 导航任务异常上报



## 2.1 请求


开发者下发导航任务后可获取响应消息，消息中携带导航任务异常码。

或可通过查询导航任务状态，响应消息中携带导航任务异常码。


## 2.2 主动上报


软件包版本≥V1.1.8 支持该接口。

basic_server 以 1Hz 固定频率向心跳来源 IP/端口主动上报。


| Type字段值 | Command字段值 | 消息类型 |
| --- | --- | --- |
| 1002 | 7 | 获取导航任务异常状态信息 |


文档中出现的所有 Type / Command 均为十进制数字。

Json示例


```json
{
    "PatrolDevice":{
        "Type":1002,
        "Command":7,
        "Time":"2023-01-01 00:00:00",
        "Items":{
            "NavStatus": {
              "Value:0,
              "Status":0,
              "ErrorCode":0,
              "LoopCnt":0,
              "RemainingCnt":0,
              "Name":"XXX"
            },
            "LocationStatus"：{
              "Location":1,
              "PosX":0.0,
              "PosY":0.0,
              "PosZ":0.0,
              "Roll":0.0,
              "Pitch":0.0,
              "Yaw":0.0
            },
          }
        }
    }
}
```


NavStatus 字段说明


| 参数项 | 含义 | 数据类型 | 单位 | 参数值说明 |
| --- | --- | --- | --- | --- |
| Value | 导航任务目标点变化 | int | / | 与下发导航任务请求对应 |
| Status | 导航任务执行状态 | int | / | 见后表 |
| ErrorCode | 错误码 | int |  | 见2.3 |
| LoopCnt | 循环次数 | uint | / |  |
| RemainingCnt | 循环剩余次数 | uint | / |  |
| Name | 导航任务名称 | string | / |  |


NavStatus.Status 导航任务执行状态


| 参数值（十进制） | 参数值（十六进制） | 含义 |
| --- | --- | --- |
| 0 | 0x0 | 空闲 |
| 1 | 0x1 | 退出充电桩中 |
| 2 | 0x2 | 导航预处理 |
| 3 | 0x3 | 导航中 |
| 4 | 0x4 | 导航完成 |
| 5 | 0x5 | 进入充电桩中 |
| 255 | 0xff | 暂停中 |


LocationStatus 字段说明


| 参数项 | 含义 | 数据类型 | 单位 | 参数值说明 |
| --- | --- | --- | --- | --- |
| Location | 定位状态 | int | / | 0：定位正常<br><br>1：定位丢失 |
| PosX/Y/Z | 机器人在地图坐标系下的坐标 | float | m |  |
| Roll/Pitch/Yaw | 机器人在地图坐标系下的姿态角度 | float | rad |  |

# 通讯错误码机制


basic_server 在收到客户端下发的每一个请求后，都会返回该条消息：

JSON 形式：


```json
{
  "PatrolDevice": {
    "Type": XXXX,
    "Command": XX,
    "Time": "2023-01-01 00:00:00",
    "Items": {
      "ErrorCode": 0,
      "ErrorMessage": "Success"
    }
  }
}
```


XML 形式：


```xml
<?xml version="1.0" encoding="UTF-8"?>
<PatrolDevice>
    <Type>XXXX</Type>
    <Command>XX</Command>
    <Time>2023-01-01 00:00:00</Time>
    <Items>
        <ErrorCode>0</ErrorCode>
        <ErrorMessage>Success</ErrorMessage>
    </Items>
</PatrolDevice>
```


其中，回复的 Type 和 Command 字段值与客户端下发的对应请求消息中的 Type 和 Command 字段值相同。

Items字段中参数项的值与含义如下（ErrorMessage与ErrorCode一一对应，用作对ErrorCode的补充描述）：


| ErrorCode<br><br>（十六进制） | ErrorCode<br><br>（十进制） | ErrorMessage | 含义/建议动作 |
| --- | --- | --- | --- |
| 0x0000 | 0 | Success | 发送成功，可继续下一步 |
| 0xE001 | 57345 | Unsupported data format | 发送的数据格式不支持（非xml和Json），建议检查帧头 Format 字段 |
| 0xE002 | 57346 | Data parsing failed | 协议格式异常，数据解析失败，缺少PatrolDevice、Items、Type、Command，建议校验 JSON/XML 格式 |
| 0xE003 | 57347 | Unsupported protocol type | 找不到Type、Command对应的协议，建议检查 Type、Command 值 |
| 0xE004 | 57348 | Missing necessary fields | 缺少协议字段 |
| 0xE005 | 57349 | Mismatched data type | 字段类型不匹配，建议校对字段类型 |
| 0xE006 | 57350 | Mismatched request client | 请求客户端不匹配，例如：轴指令发送时，要求2s内发送的指令来自同一个客户端 |
| 0xE007 | 57351 | No operation permission | 无操作权限 |
| 0xE008 | 57352 | Not allowed operation | 当前状态下不允许的操作，建议检查状态机（如未站立不能发速度） |
| 0xE009 | 57353 | Operation failure | 操作失败，建议查看 `Type=1002, Cmd=3` 错误详情 |
| 0xE00A | 57354 | Unsupported function | 不支持的功能，例如：导航功能只有Pro版本支持，建议确认固件版本 |
| 0xE00B | 57355 | Internal error | 内部错误，如内部文件打开失败，内部文件解析失败等，建议查看日志 |


注意：`ErrorCode=0x0000` 仅表示命令已被接收并触发，不代表业务执行成功。
