# 导航与巡检的断联策略

单点导航与多点巡检默认由 GOS 机载寻路执行。电脑持续失联 5 秒时，GOS 请求停车。平台维护任务心跳，浏览器负责显示任务状态。 [机载寻路与巡检](gos-patrol.md)

需要断联后完成任务或沿原路返回时，在巡检页把「寻路方式」设为「原厂导航」，选择断联策略并保存路线。可在离线时编辑和保存这些选项。执行需要 NOS 驻机导航就绪，并使用自动接续、低速敏捷平地、自主导航及正向行走。到点任务、沿途采集和含充电航点的路线使用断联停车。

在连接中心打开「NOS · 导航主机」的「原厂导航断联策略」，填写该机器已核对的机内 AOS IPv4 地址，然后点击「更新服务」。机内 AOS 地址可与电脑访问机器人使用的外网地址不同。留空并更新服务可关闭驻机续行与返程。执行前平台会核对 NOS 支持的策略。

## 任务状态

重连时，电脑先核对原任务与停车反馈。操作者点击「结束任务」后，收到对应回执并观察到停稳反馈，页面才显示停止完成。雷达、定位和控制反馈由 GOS 在机内持续核对。

## 接口

- `GET /api/nav/resident/capabilities` 查看 GOS 机载服务能力。
- `POST /api/nav/cancel` 请求结束当前任务。平台快照的 `resident_navigation` 同步机载状态。
- GOS 提供 `/missions/capabilities`、`/missions/status`、`/missions/start`、`/missions/pulse` 和 `/missions/cancel`。已有 NOS 驻机任务的引用仍可用于状态与停车核对。
