# 验证范围与报告

验证结果必须注明范围。源码通过、合成行为通过、录制回放通过、代理部署成功和实机任务完成不是同一件事。

| 层级 | 入口与材料 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 便携检查 | `tools/check_portable.py`、合成用例、语言 guard、本机构建 | 被选择的数学/状态/页面逻辑及当前原生 ABI 在该环境中的回归结果 | 真实地图质量、现场网络时序、机器人动作、未选中的测试 |
| 严格本机离线验收 | `tools/offline_acceptance.py`、私有录制与来源哈希、本机基线、macOS 网络沙箱 | 指定录制事实的回放、来源一致性和该验收定义的完整覆盖 | 新现场动作或其他 OS 的系统隔离能力 |
| 设备只读核查 | 已授权环境中的协议、服务、日志和数据读回 | 当前设备/固件/数据链路的事实 | 行走成功、停止完成、候选地图可用 |
| 实机验证 | 明确授权的现场任务与监督、执行日志、实际反馈 | 本次环境与版本下实际发生的结果 | 未测试环境、其他设备、长期稳定性 |

## 便携检查

macOS/Linux 完整便携组：

```bash
python tools/check_portable.py --report .artifacts/portable/report.json
```

Windows 支持范围内的子集：

```powershell
python tools/check_portable.py --groups algorithms,navigation,sensing,ui --report .artifacts/portable/report.json
```

这条 Windows 命令报告 `partial`。POSIX 文件/服务生命周期和原生 C++ 组未执行，不能将绿色子集任务等同于完整原生验证。完整默认组在不支持的 OS 或缺少必需编译器时不能报告通过。

### 选择的测试

便携 runner 使用固定白名单，不默认执行整个 `unittest discover`：

- `algorithms`：自主恢复、遮挡房间探索、连续几何运动、控制时钟、地形建议、纯显示位姿监测。
- `navigation`：机身通行空间、目标规划、临时通行观测与定位匹配的合成几何。
- `sensing`：最新帧、观测过期、只读感知接口和完整点集 NumPy 等价性。
- `maps`：结构配准、变化证据、保留原图以及保存结果的独立合成合同用例。
- `lifecycle`：请求归属、重复调用、后台线程启动失败和源码交付边界。
- `native`：当前 C++ 库的 ABI、完整随机点集/大点集输出一致性、边界回退与原生调用证据。
- `ui`：在 Node VM 中运行的页面状态、取消/迟到响应、画面和地图选择回归；不是实际浏览器渲染或视频验收。

具体测试 ID 与数量以每次 JSON 报告为准。私有位姿回放方法、真实保存报告回放类，以及未审查的硬件/回环服务、模型推理、FFmpeg 或其他测试不自动进入白名单。纯测试可能覆盖同一功能的一部分，但不能据此把被排除的真实用例标为通过。

### 执行边界

Runner 先把源码、所需测试代码及公共错误说明复制到临时目录。它不复制 `data/`、真实回放 JSON、模型权重、作者资料目录或已有本机二进制；测试不会因开发机恰好有私有地图而获得额外输入。

Python guard 阻止网络调用、子进程和摄像头打开，也禁止访问暂存目录中的运行数据/录制路径。Node guard 阻止网络、DNS、HTTP、全局 fetch/WebSocket 与子进程；测试在同一个 Node 进程中加载，不依赖子进程测试隔离。所有正向用例使用合成输入或模拟响应。

**这些语言 guard 不是 OS 安全沙箱，也不是执行恶意代码的隔离方案。** 原生扩展可能绕过语言 hook，所以白名单与依赖审查仍然必要。严格本机验收的系统级网络隔离能力没有被移植或冒称为便携 runner 的能力。

Worker 在安装测试 guard 前，仅预热标准库 `platform.uname()` / `platform.machine()` 缓存，并在报告的 `host_metadata` 中记录边界。Windows 标准库必要时执行只读 `ver` 查询；准备函数只接受其三个精确命令形式。guard 安装后包括 `cmd /c ver` 在内的所有测试子进程仍被禁止，并再次验证平台信息可从缓存读取。NumPy、OpenCV 和产品模块仍在 guard 之后导入。独立回归可运行 `python -m unittest discover -s tests -p "test_portable_host_metadata.py" -v`；它仅启动本地 Python 子进程来验证不可卸载的审计 hook，不属于产品测试白名单，也不替代 Windows 托管 CI 的实际结果。

依赖安装是 CI 的独立准备步骤，可以从公开包源取依赖；测试阶段不下载依赖、模型或资料，不使用额外私密 secret。GitHub 工作流只请求只读仓库权限。

### 原生后端证据

完整便携组显式编译临时原生库，并设置 `M20_REQUIRE_NATIVE_SENSING=1`。缺库、错误 ABI 或构建失败是失败，不能跳过后报 PASS。

报告记录原生命中和回退数量，并要求现有测试实际通过“120 个随机完整点集无隐藏回退”和“100k/150k/300k 完整输入走原生”的断言。边界与异常输入的预期回退仍然单独测试并统计；总回退次数非零不等于失败，但原生命中为零绝不能通过。

这些是合成数据上的功能证明，不是传感器实测帧率、机器人 CPU 延迟或现场避障验证。

### 结果与跳过

报告包含环境版本、被测源码 SHA-256、选定组、成功/失败/跳过测试、未选择测试的 ID/数量/原因、原生构建与命中证据，以及检查期间源码是否变化。测试日志会清除本机工作区和临时目录的绝对路径。

- `passed`：完整的**便携白名单**通过；其他验证层级仍未覆盖。
- `partial`：显式选定的子集通过；报告列出的组没有执行。
- `not_verified`：缺少运行工具、OS 不支持、意外 skip 或检查期间源码变化，无法给完整结论。
- `failed`：构建、断言、语法或 effect guard 失败。

退出码 `0` 表示请求的检查通过（可能仍是 `partial`），`1` 表示失败，`2` 表示未完整验证。报告比退出码表达更多范围信息，PR 应同时写明 status 和执行/跳过数量。

缺少私有 fixture 时不创建替代“现场记录”。正常便携选择直接排除对应回放；严格本机验收仍按它自己的规则报告缺失。新测试需先审查再加入白名单，不能靠跳过失败用例获得绿色结果。

## 严格本机与现场

`tools/offline_acceptance.py` 是独立入口，包含已录制故障、私有来源校验与测试基线。只在具备相应数据和系统沙箱的原开发/验收环境运行。其 `--record-baseline` 只有在实际满足覆盖条件时才应使用；不将便携报告复制为该基线。

实机测试另记录型号/固件、实际运行源码、地图与现场条件、执行者、任务边界、真实反馈和保存结果。协议 ACK、UI 出现路线、原生命中、地图点数增加或“服务已启动”，都不能单独作为行走完成或地图精度提高的证据。

## Windows 独立工具链检查

`portable-checks.yml` 的独立 Windows MSVC 作业准备编译环境、构建当前源码的 `.pyd`，要求 `test_native_sensing` 实际命中原生实现并与 NumPy 数值一致，同时执行无网络的本机 OpenSSH 参数检查。该作业与受 effect guard 约束的 Windows Python/Node 子集分开报告；不会由模拟响应或 Mac 编译结果替代。
